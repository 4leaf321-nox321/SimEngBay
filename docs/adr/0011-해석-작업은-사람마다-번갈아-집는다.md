# 0011. 해석 작업은 사람마다 번갈아 집는다 — 대기 중이면 줄의 어디쯤인지 말한다

- 상태: 채택
- 날짜: 2026-10-21
- 관련: [ADR 0010](0010-해석용-MCP.md)(MCP 로 DOE 를 통째로 걸기 쉬워졌다) · 운영 안내서 「솔버를 갈라 띄우기」

## 결정

1. **워커는 같은 솔버 안에서 사람마다 번갈아 집는다**(`services.claim_next`). 대기 작업을 고르는 순서:
   1. 그 사람의 **지금 도는 작업 수**가 적은 것 — 워커가 여럿일 때 한 사람이 모든 워커를 차지하지 않게.
   2. 그 사람이 **마지막으로 집힌 때**가 오래된 것(한 번도 안 집힌 사람이 먼저) — 워커가 하나여도 번갈아
      돈다. ①만 두면 워커가 비는 순간 모두 0 이라 먼저 건 사람의 작업만 계속 집힌다.
   3. **먼저 건 것** — 한 사람의 작업끼리는 지금처럼 먼저 건 순서다.

   셋 다 같은 솔버 안에서 센다(Ansys 워커는 Ansys 줄, CalculiX 워커는 CalculiX 줄). 그대로
   `FOR UPDATE SKIP LOCKED` 한 줄이라 워커 여럿이 같은 작업을 집지 않는다.

2. **대기 중인 작업은 줄의 어디쯤인지 말한다** — 작업 상세(`SimulationOut.queue`)와 MCP `job_get`:
   그 솔버의 대기 수 · **내 앞의 내 작업** · **줄을 나눠 쓰는 사람 수** · 지금 도는 것 · 그 솔버를 집는
   살아 있는 워커 수(0 이면 움직이지 않는다고 경고). 번갈아 집으므로 「앞에 선 남의 작업 수」 로는 내
   차례를 말할 수 없다 — DOE 수백 점 뒤에 선 것처럼 읽힌다.

3. **워커 수를 운영이 맞추게 한다.** 서버 화면의 「워커 · 솔버」 가 CalculiX 워커가 하나뿐이면 말하고,
   운영 안내서가 「워커 수 = 동시에 도는 해석 수, CalculiX 는 코어 수에 맞춘다」 를 예와 함께 적는다.
   Ansys 는 노드락 라이선스라 하나가 정상이다.

## 배경

해석 작업은 DB 를 큐로 쓴다(`simulations.status = 'queued'`, 워커가 하나씩 집는다). 지금까지는 먼저 건
순서(`ORDER BY created_at`)였다. 사람마다 한두 건씩 걸 때는 문제가 없었는데, DOE 가져오기는 설계점
수만큼 작업을 한 번에 만들고, MCP(ADR 0010)로 AI 가 DOE 를 통째로 걸기 쉬워졌다 — A 가 200점을 먼저
걸면 B 가 바로 뒤에 건 한 건은 같은 솔버의 200건이 다 끝날 때까지 기다린다. 기본 워커 수가 1 이라
운영에서 늘리지 않으면 모든 해석이 그 한 줄이었고, 화면 · AI 모두 「대기」 만 보여 얼마나 기다릴지
몰랐다.

## 대안

- **사람마다 동시 실행 상한**(예: 한 사람 4건까지) — 워커가 놀고 있어도 상한에 걸리면 안 돈다. ①이 같은
  효과를 워커를 놀리지 않고 낸다.
- **우선순위(한 건짜리 먼저 · DOE 나중)** — 「급한 한 건」 과 「급한 DOE」 를 가릴 수 없고, 우선순위를
  사람이 매기게 하면 다들 높게 매긴다. 번갈아 집기가 한 건짜리를 이미 앞에 세운다.
- **DOE 를 한 덩어리로 집기** — 설계점마다 워커가 달라야 여러 점이 동시에 돈다.
- **정확한 순번(N번째)** — 번갈아 집는 줄에서 순번은 남이 새로 거는 순간 바뀐다. 「내 앞의 내 작업 ·
  나눠 쓰는 사람 수」 가 거짓말하지 않는 가늠이다.
