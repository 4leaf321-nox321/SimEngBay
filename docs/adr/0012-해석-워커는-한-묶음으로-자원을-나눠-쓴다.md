# 0012. 해석 워커는 한 묶음으로 자원을 나눠 쓴다 — 멈출 때는 솔버까지 그룹째

- 상태: 채택
- 날짜: 2026-10-23
- 관련: [ADR 0011](0011-해석-작업은-사람마다-번갈아-집는다.md)(줄) · 운영 안내서 「워커 묶음」

## 결정

1. **멈출 때는 프로세스 그룹째.** 단계 실행기(자식 파이썬)를 새 세션으로 띄우고(`start_new_session`),
   취소 · 시간 초과 때 그 **프로세스 그룹**에 TERM → (15초) → KILL 을 보낸다. 자식이 먼저 끝나도 끝에 그룹에
   한 번 더 보낸다(`subprocess_executor._stop`).

2. **워커 전부를 한 systemd slice 에 묶는다**(`<slug>-workers.slice`). `deploy.sh` 가 설치 · 업데이트 때 **그
   서버를 재서** 앱 · DB · 운영체제 몫(코어 max(2, 1/8) · 메모리 max(4 GB, 1/5))을 남기고 나머지를
   `CPUQuota` · `MemoryMax` 로 쓴다. `MemorySwapMax=0` · `CPUWeight=20` · `IOWeight=20`, 워커 유닛은
   `Nice=10` · `OOMScoreAdjust=500`. 사람이 정한 값(`WORKER_CPU_PERCENT` · `WORKER_MEMORY_MAX`)은 설치 기록에
   남는다.

3. **메모리 부족은 그렇다고 말한다.** 솔버(gmsh · ccx)나 단계 실행기가 KILL 로 끝났으면 — 우리가 보낸 것이
   아니므로(취소는 TERM 이 먼저다) — 운영체제가 메모리가 모자라 끊은 것이다. 실패 코드 `out_of_memory` 와
   「요소 크기를 키우거나 워커 수를 줄이세요」.

4. **권장 워커 수를 말한다.** 묶음 상한 ÷ 한 해석(코어 2 · 메모리 4 GB)으로 코어 · 메모리 둘 다 넘지 않는
   수를 `deploy.sh` 가 찍고, 그보다 많으면 경고한다(막지는 않는다 — 묶음이 지킨다).

## 배경

운영 서버에서 해석을 돌리자 **메모리가 바닥나 서버째 멈췄다**(2026-10-23). 같은 날, DOE 의 작업 하나를 취소했더니
목록에서는 사라졌는데 서버에는 **CalculiX 프로세스 6개**가 돌고 있었다. 원인 둘:

- 취소 · 시간 초과가 **직계 자식(단계 실행기 파이썬)만** 멈췄다. 그것이 `subprocess.run` 으로 띄운 gmsh · ccx 는
  고아가 되어 계속 돌았고, 워커는 다음 작업을 집어 솔버가 쌓였다(시험으로 재현했다 — 옛 동작이면 손자가 산다).
- 워커에 **자원 상한이 없었다.** 해석이 몰리면 앱 · DB 와 같은 자리에서 메모리를 다투고, 스왑으로 버티는 동안
  서버 전체가 응답하지 않았다. 운영 안내서의 예시(16코어에 워커 8 × 2코어)도 앱 · DB 몫을 안 남겼다.

## 대안

- **워커마다 `MemoryMax`** — 워커 수만큼 나눠야 해서 큰 해석 하나가 작은 칸에 갇힌다. 묶음 하나면 큰 해석이
  남는 몫을 쓰고, 넘으면 그때 가장 큰 것이 끊긴다.
- **해석 전에 메모리를 어림해 기다리게** — 절점 수로 메모리를 맞히기 어렵고(솔버 · 차수 · 해석 종류마다 다르다),
  틀리면 놀거나 끊긴다. 지금은 운영체제의 상한이 정확하다. 필요해지면 줄(ADR 0011)에 붙인다.
- **기본 워커 수를 자동으로 늘리기** — 솔버를 안 가른 워커는 Ansys 작업도 집는다(노드락 라이선스가 하나라
  둘째부터 실패한다). 그래서 권장만 말한다.
- **`KillMode` 에 맡기기** — 워커가 죽거나 다시 뜰 때는 systemd 가 cgroup 째 정리하지만, 워커가 살아 있는 채
  작업 하나를 취소할 때는 아무도 손자를 안 멈춘다.

## 결과

- 시험: `tests/unit/test_executors.py`(취소하면 자식이 띄운 손자까지 끝난다 · KILL 로 끝난 단계와 솔버는
  `out_of_memory`), `tests/api/test_deploy_render.py`(16코어 · 64 GB 서버의 묶음 상한 · 워커 유닛이 묶음에 든다 ·
  작은 서버에 워커가 많으면 권장 수 · 사람이 정한 상한은 기억), 화면 문구는 `test_simulation_labels.py` 가
  실패 코드와 견준다.
- 운영: `deploy.sh update` 한 번이면 묶음이 선다. 옛 판에서 남은 고아 솔버는 워커를 다시 띄우면 함께 끝난다.
- 남은 것: Ansys(Mechanical)가 띄우는 솔버도 같은 그룹에 들지만, Windows 다리(`windows-bridge`)로 띄운 것은 그
  기계의 일이다(개발 PC).
