# 0008. 해석 작업은 건 사람의 것 — 게시해야 남이 본다

- 상태: 채택
- 날짜: 2026-10-20

## 결정

해석 작업은 **건 사람의 것**이다. 보는 것은 건 사람과 시스템 관리자뿐이고, 건 사람이 **게시**한 끝난
작업(`simulations.published_at`)은 조직의 누구나 읽는다. 바꾸는 일(재시도 · 취소 · 정리 · 지우기 · 게시 · 해제 ·
실측 · 메시 수렴 점검)은 건 사람이나 시스템 관리자만 한다 — 남의 게시 결과는 읽기만 한다. 부서
관리자도 게시 전의 부서원 작업은 못 본다.

- 게시는 **끝난 작업만**. 메시 수렴 수준 작업은 원래 작업을 따른다(함께 게시 · 해제, 게시 뒤에 끝난
  수준은 끝날 때 따라 게시).
- DOE 는 스터디째 게시 · 해제한다 — 내가 건 끝난 설계점만.
- 게시는 복사가 아니라 표시다. 끝난 작업의 결과는 바뀌지 않고, 작업을 지우는 길도 없다.
- 이미 끝난 작업은 마이그레이션(0008_publish)이 게시된 것으로 옮겼다. 실패 · 취소 · 대기 · 도는 중인
  작업은 건 사람의 것으로 남았다.
- 작업의 `owner_workspace_id`(부서)는 남는다 — 목록 · 통계의 꼬리표이고, 거는 것은 여전히 그 부서의
  멤버다.

## 배경

전에는 부서 단위로 열려 있었다(전역 + 열린 부서 + 내 부서 — `open_owner_clause`). 「우리 조직에 이
형상의 모달 해석이 있나」 에 답해 같은 해석을 두 번 안 돌리려는 것이었는데, 해석은 시행착오가 많다 —
실패한 작업, 메시만 바꿔 본 작업, 메시 수렴 점검의 수준 작업까지 모두에게 보여, 남이 어느 것을 믿고
써야 할지 알 수 없었다. 같은 사람들이 쓰는 CompCore 는 이미 「내 작업 공간 · 등록」 꼴이다.

해석용 MCP 를 만들기 전에 정해야 했다 — MCP 의 「작업 목록」 이 무엇을 뜻하는지가 이 결정에 달렸다.
PAT 는 화면과 같은 범위를 본다.

## 대안

- **부서 단위로 열어 둔다(전과 같이)** — 시행착오가 남에게 보이는 문제가 그대로 남는다.
- **CompCore 처럼 게시할 때 복사본을 만든다** — 해석 결과는 끝나면 바뀌지 않고 지우는 길도 없어서
  복사할 까닭이 없다. 복사본은 두 벌이 되고, 실측 · 메시 수렴처럼 작업에 붙는 것을 어느 쪽에 붙일지
  정해야 한다.
- **게시 범위를 부서로 한다** — 「조직에 이 해석이 있나」 에 답하지 못한다. 가리고 싶은 결과는 게시하지
  않으면 된다.

## 결과

- 「같은 해석을 두 번 안 돌린다」 는 게시된 결과로 지킨다. DOE 가져오기는 스터디 단위로 한 번이라,
  남의 게시 전 작업과 겹치면 **누구 것인지 말하고** 막는다(보이지 않는 것 때문에 막히면 찾을 길이 없다).
- 해석 화면에 **두 번째 사이드바**를 둔다 — 「개인 작업」(기본) · 「공용 작업공간」 · 「전체」(시스템
  관리자), 각각 해석 작업 · DOE 비교(`SimulationsLayout`, 주소의 `?scope=`). 선택 상자 하나로 두면
  지금 내 책상을 보는지 게시판을 보는지 잃는다. 홈의 「남은 일」 은 내 실패만 센다(시스템 관리자는
  전부).
- 게시 · 해제는 감사 기록에 남는다(`simulation.published` · `study.published` …).
