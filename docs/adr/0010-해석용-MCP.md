# 0010. 해석용 MCP — 흐름 단위 도구 20개, 입력은 스키마 · 결과는 서버가 맞춘 값

- 상태: 채택
- 날짜: 2026-10-21
- 관련: [ADR 0008](0008-해석-작업은-건-사람의-것-게시해야-남이-본다.md)(무엇이 보이나) ·
  [ADR 0009](0009-HWAX-포털에-붙이기.md)(게이트웨이 위임) · Standard Platform ADR 0028 결정 12 · 13 ·
  `mcp_server/README.md` · 운영 안내서 9절

## 결정

AI(Claude Code · Claude Desktop · HWAX 포털의 Claude)가 해석을 걸고 결과를 읽게 하는 MCP 서버를 둔다 —
`mcp_server/server.py`, 별도 프로세스 · 별도 venv, 기본 `127.0.0.1:<앱 포트+2>/mcp`(8072). Standard
Platform · ComponentCore 의 MCP 와 같은 꼴이다.

1. **사용자의 토큰으로만.** 들어온 `Authorization` 을 그대로 백엔드에 넘긴다 — 권한(건 사람 · 게시) ·
   범위(`simulations:write`) · 검증은 전부 백엔드가 한다. MCP 에 규칙을 두지 않는다. 하나 있는 기본값은
   **화면과 같은 것**이다: `jobs_create` 에 부서를 안 주면 새 작업 창처럼 대표 부서(없으면 첫 소속) —
   비워 보내면 서버가 전역 작업으로 읽고 시스템 관리자가 아니면 거절한다.

2. **도구는 작업 흐름 단위로 20개에 고정.**

   | 흐름 | 도구 |
   | --- | --- |
   | 안내 · 나 | `get_guide` · `whoami` · `recipe_schema` |
   | CAD 폴더 | `folder_find` · `folder_browse` · `folder_preview` |
   | 걸기 · 보기 | `jobs_create` · `jobs_list` · `job_get` · `job_result` · `job_retry` · `job_cancel` |
   | 견주기 | `studies_list` · `study_get` · `convergence_start` · `convergence_get` · `measurement_add` · `measurements_get` |
   | 게시 | `job_publish` · `study_publish` |

   해석은 **CAD 공용 폴더에서만** 건다(`doe/import` — 설계점 하나 · 여럿 · 폴더 통째로). STEP 을 올리는
   도구는 없다 — 화면도 CAD 폴더가 기본이고, 형상 바이트를 AI 가 나르게 할 까닭이 없다.

   **CompCore 에서 온 것은 스터디 id 로 찾는다 — 사용자에게 경로를 묻지 않는다**(`folder_find`, 개발
   서버에 붙여 써 보고 더했다). MCP 사용자는 공유 폴더가 어디인지 모르고 CompCore 에서 붙인 이름이나
   스터디 id 만 안다. CompCore 는 내보낼 때 `<이름>-<스터디 id 앞 8자리>` 폴더를 만들고 `study.json` 에
   id 를 적는다 — 두 플랫폼을 잇는 열쇠가 그 id 다(우리 `study_id` 와 같다). CompCore `doe_export` 가
   주는 `folder` 는 Windows 경로(`F:\…`)라 이 서버의 경로(`/mnt/f/…` · 컨테이너의 `/data/doe`)와 글자로
   맞지 않는다. 그래서 **`GET /simulations/doe/find?q=`** 가 뿌리 아래 두 단까지의 스터디 폴더를 id(전체 ·
   앞 6자리 이상)나 이름(공백 · `_` · `-` 무시)으로 찾는다 — id 로 맞은 것이 먼저, 그다음 최근에 내보낸 것.
   못 찾으면 「CompCore 에서 내보내기(공유 폴더는 30일짜리 전달 큐)」 를 말한다. 안내문 · 안내서가 두 MCP 를
   함께 쓰는 흐름(`doe_create` → `doe_run` → `doe_export` → `folder_find` → `folder_preview` →
   `jobs_create`)을 적는다.

3. **해석이 늘어도 MCP 는 그대로 — 입력은 스키마, 결과는 서버가 맞춘 값.**
   - 입력: `recipe_schema` 가 `GET /simulations/recipes`(스펙 정의 `SPEC_MODELS` 에서 뽑은 JSON 스키마)를
     그대로 준다. 스펙은 dict 로 넘기고 검증은 백엔드가 한다.
   - 결과: 새 엔드포인트 **`GET /simulations/{id}/values`** — 스터디 비교 · 메시 수렴 · 실측 맞추기가 보는
     견줄 값(`app/core/values.py`, **늘 mm · MPa · N · Hz**)을 작업 하나로. 결과 파일은 레시피 · 솔버마다
     칸과 단위가 달라(Ansys 를 SI 로 돌리면 m · Pa) 읽는 쪽마다 맞추면 언젠가 하나가 1000배 틀린다.
     모달은 `result.json` 의 모드 방향 · 유효질량비를 곁들이고, 원본은 `detail=true` 일 때만.

4. **오래 걸리는 일은 기다리되 지어내지 않는다.** `jobs_create` 는 작업 id 를 바로 돌려준다. `job_get` 의
   `wait_seconds`(최대 25초 — 클라이언트의 도구 시간 한도보다 짧게)는 폴링 경로(`/status`, 접근 로그에 안
   남는다)를 2초마다 묻고, 안 끝났으면 도는 상태와 `next`(다음 할 일)를 준다.

5. **게시는 사람이 판단할 일.** `job_publish` · `study_publish` 를 두되(사용자가 원했다, 2026-10-21) 안내문 ·
   안내서 · 도구 설명이 모두 「사용자가 시킬 때만」 을 말한다. 정리(`tidy` — 중간 파일을 지운다, 되살릴 수
   없다) · 실측 내리기는 도구로 두지 않는다 — 화면에서.

6. **HWAX 게이트웨이와 같은 신호를 쓴다**(Standard Platform ADR 0028 결정 12 · 13).
   - 백엔드 401 은 결과가 아니라 예외 `BackendUnauthorized` — FastMCP 가 `Error executing tool <이름>:
     <METHOD> <경로> → HTTP 401: …` 로 감싸 게이트웨이의 「위임 토큰을 새로 받아 한 번 다시」 정규식에
     맞는다. 401 밖의 오류는 서버의 말 그대로 결과로(다시 부르면 쓰기가 두 번 돈다).
   - 위험 도구 `DESTRUCTIVE_TOOLS = {job_cancel}` — 게이트웨이는 이름이 `cancel_` 로 **시작**해야 막는다.
     요청서 7절이 `_INVOKE_DENY_EXACT` 에 넣어 달라고 하고, 시험이 코드의 목록과 요청서 틀을 견준다.
   - `Authorization` 만 넘긴다 — 게이트웨이가 싣는 소속 머리는 버린다.

7. **안내서는 서버가 쥔다.** `guide/GUIDE.md` 를 `<!--@ 주제 -->` 로 갈라(`overview` · `run` · `conditions` ·
   `results` · `compare` · `publish`) `get_guide` 가 준다 — 조건의 걸림 · 넘김 · 거절, 솔버마다 걸 수 있는
   것, 첨두응력을 믿지 말 것, 모드 추적, 게시는 사람이.

8. **포털 연동 마무리.** ADR 0009 때 MCP 가 없어 미뤘던 것을 함께 옮겼다 — `deploy.sh hwax-request`(요청서 ·
   위임 비밀) · 요청서 틀(`docs/[참고] HWAX포탈_연동_요청서.md`) · `MCP_PUBLIC_URL`(화면의 Claude 연결 안내 ·
   포털 뒤 진단) · 「내 정보」 의 「AI 도구 연결」(Standard Platform 의 `McpSetupGuide`).

## 배경

MCP 를 미뤄 온 까닭은 「해석 구조가 바뀌면 MCP 도 계속 고쳐야 한다」 였다. 그 사이에 둘이 섰다 — 입력 칸은
스펙 정의에서 뽑은 스키마가 정본이 됐고(`recipes` 가 조화를 빠뜨리던 것을 고쳤다, 2026-10-20), 무엇이
보이는지는 ADR 0008(건 사람 · 게시)로 정해졌다. 결과는 레시피마다 모양이 달라도 견줄 값은 한 모양이다
(`values.Values`). 그래서 MCP 가 해석 종류를 몰라도 된다.

## 대안

- **레시피마다 도구(`modal_run` · `static_run` …)** — 해석이 늘 때마다 도구가 는다. 도구 목록이 길수록
  모델은 엉뚱한 것을 고른다(Standard Platform 의 결론).
- **MCP 가 `result.json` 을 읽어 단위를 맞춘다** — `values.py` 의 두 벌이 생기고, 갈리면 화면과 AI 가 다른
  숫자를 말한다.
- **STEP 업로드 도구** — 화면의 기본도 CAD 폴더다. AI 가 형상 바이트를 나를 까닭이 없고, 회사 PC 의 DRM 으로
  로컬 파일은 대개 열리지 않는다.
- **게시는 도구로 안 둔다** — 「이 결과를 공유해」 를 화면으로 돌려보내게 된다. 사용자가 원했고, 게시는
  되돌릴 수 있다(해제).
- **`jobs_create` 가 부서를 비워 보낸다** — 서버는 전역 작업으로 읽어 관리자가 아니면 거절한다. 사람은 「부서를
  고르세요」 를 AI 에게서 받고 왜인지 모른다. 화면의 기본을 그대로 따른다.
