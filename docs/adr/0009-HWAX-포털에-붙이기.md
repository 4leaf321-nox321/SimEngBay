# 0009. HWAX 포털에 붙이기 — 포털 로그인(jwt-handoff) · 게이트웨이 위임 창구 넷

- 상태: 채택
- 날짜: 2026-10-21
- 관련: Standard Platform ADR 0028(이 결정의 원본 — 코드도 거기서 옮겼다) · ComponentCore 의 같은 창구 ·
  운영 안내서 9절

## 결정

HWAX 포털이 세 플랫폼(Standard Platform · ComponentCore · SimEngBay)에 기대하는 **네 창구를 같은 계약으로**
갖춘다. Standard Platform 커밋 a397d76(포털 로그인 · 게이트웨이 위임)과 a03dfc8(연결 점검)을 옮겼다.

| 창구 | 하는 일 |
| --- | --- |
| `POST /api/auth/portal-callback` | 포털의 RS256 launch 토큰을 포털 JWKS 로 확인하고 우리 세션(refresh 쿠키)을 연다 → 303 |
| `POST /api/auth/sso` | 게이트웨이가 사람마다 그 사람 명의의 하루짜리 개인 토큰 「HWAX 게이트웨이(<client>)」 를 받는다 |
| `POST /api/auth/sso/verify` | 연결 점검 — 꺼짐 · 주소 · 비밀까지만 보고 204. 계정 · 토큰 · 감사를 건드리지 않는다 |
| `POST /api/auth/sso/revoke` | 그 사람의 위임 토큰을 회수한다 |

- **포털 로그인**: RS256 만, `iss` · `aud`(`PORTAL_AUDIENCE`, 기본 slug) · `exp` · `nbf`(여유 10초) ·
  `scope == "launch"`. `jti` 는 DB 에 적어 한 번만(`portal_launch_jtis`, 0009 — 워커 · 이중화 서버가 같은 토큰을
  받을 수 있다). 사람은 email 먼저, 없으면 sub. sub 로만 맞은 시스템 관리자에는 붙이지 않는다. 처음 보는 사람은
  **가입 신청(승인 대기, 희망 부서 없음)** 으로 만든다 — 계정 화면의 「승인」 이 그때 부서를 묻는다.
- **꺼짐은 404 JSON** — 포털 `update-all` 의 진단표가 그 숫자로 「꺼짐」 을 읽는다. `PORTAL_JWKS_URL` 이 없으면
  콜백이, `HEAX_SSO_SECRET` 이 없으면 위임 창구 셋이 꺼진다. 안 붙이는 설치는 둘 다 비워 둔다.
- **위임 계약은 RA 그대로** — 머리 `X-Heax-Gateway-Secret` · `X-Hwax-Delegate-Email`(먼저) /
  `X-Heax-User-Email` · `X-Heax-Client`. 꺼짐 404 → 허용 주소 밖 403 → 비밀 401 순서로 보고(`_guard`), 발급 ·
  회수는 그 뒤에 이메일(없으면 400)과 사람(처음 보는 사람 · 대기 · 정지 · 삭제는 403 + 한국어 한 줄)을 본다.
  처음 보는 사람을 만들지 않는다 — 포털 로그인이 가입 신청을 만드는 문이 따로 있다.
- **위임 토큰은 개인 토큰(PAT)** — 범위 `read` + 등록된 쓰기 범위 전부(관리 범위는 없다), 같은 client 의 직전
  토큰은 회수하고 죽은 줄은 지운다. 위임 토큰은 칸(`personal_access_tokens.delegated_client`, 0010)으로 가린다.
- **통로를 남긴다** — 감사 `auth.portal_login`(통로 `hwax-portal`) · `account.portal_requested` ·
  `auth.gateway_delegated` · `auth.gateway_delegation_revoked`(통로 `hwax-gateway`), 위임 토큰으로 든 요청도
  `hwax-gateway`. 접근 로그 종류 `PORTAL_LOGIN` · `GATEWAY_SSO`(발급 · 회수 · 점검, 거절 포함) · `GATEWAY_API`.
- **진단 한 자리** — `GET /api/auth/portal-status`(시스템 관리자) · 관리 › 서버의 「HWAX 포털 로그인」: 켜졌나 ·
  공개 키를 지금 받아 보고 닿나 · 설정끼리 안 맞는 것 · 위임의 마지막 발급 · 마지막 거절.
- **배포는 준 것만 적는다** — `sudo PORTAL_JWKS_URL=… PORTAL_LAUNCH_URL=… ./deploy.sh update` 가 그 값만
  `.env` 에 적고, 접두어 · `TRUST_PROXY` 가 없으면 더한다. 위임 비밀은 env 로 받지 않는다(손으로 적는다).

## 배경

HWAX 포털(`https://hwax.sec.samsung.net`)은 사내 앱을 `/<id>/` 경로로 모으고, 타일을 누르면 포털에 로그인한
그 사람으로 앱에 들어가게 한다. 포털의 Claude 게이트웨이는 앱마다 사람별 위임(`/api/auth/sso`)으로 그 사람 명의의
토큰을 받아 앱의 MCP 를 부른다. Report Archive 가 먼저 이 길로 붙었고, Standard Platform 이 같은 길을
ADR 0028 로 옮겼다. 세 플랫폼이 창구 넷을 **같은 계약**으로 갖추기로 했다(2026-10-21) — 포털 담당이 앱마다
다른 규칙을 외우지 않게.

SimEngBay 는 Standard Platform 의 포크라(ADR 0005) 인증 · 접두어 설치 · 감사가 같은 모양이어서 그대로 옮겼다.

## 우리 쪽에서 다른 것

- **MCP 서버가 아직 없다.** 위임 창구는 서 있지만 게이트웨이가 부를 도구가 없다 — 포털 담당에게 게이트웨이
  백엔드(MCP 주소) 등록은 아직 요청하지 않는다. Standard Platform 의 MCP 관련 진단(`MCP_PUBLIC_URL`)은 뺐고,
  연동 요청서를 만드는 `deploy.sh hwax-request` 도 옮기지 않았다(요청서가 MCP 를 전제한다). 해석용 MCP 를
  만들 때 둘을 더한다 — 위임 쪽은 바뀌지 않는다.
- **정지는 요청마다 막는다.** Standard Platform 은 정지할 때 세션을 끊고(`revoke_sessions`) 이미 받은 access 를
  세대(`session_epoch`)로 막는다. SimEngBay 는 인증이 요청마다 계정 상태를 다시 보므로(`ensure_can_sign_in`)
  정지 즉시 refresh · access 가 모두 403 이다 — 세대가 필요 없다.
- **위임 토큰의 쓰기 범위**는 우리 레지스트리에 등록된 것(`simulations:write` 등)이다 — 같은 코드가 등록된 것을
  읽는다(`scopes.write_scopes()`).

## 대안

Standard Platform ADR 0028 의 「대안」 을 그대로 따른다 — 포털 세션 쿠키를 직접 읽기 · jti 를 메모리에 ·
처음 보는 사람을 바로 활성으로 · 포털 `groups` 로 부서 짐작 · 위임에 세션 JWT 주기 · 게이트웨이가 처음 보는
사람을 만들기(JIT)를 모두 버렸다. 우리만의 대안 하나:

- **MCP 가 생길 때까지 위임 창구를 미루기** — 포털이 세 플랫폼을 같은 진단으로 돌리는데 우리만 405(없는
  창구)이면 「옛 판」 으로 읽힌다. 창구는 MCP 와 상관없이 서 있을 수 있고(토큰 발급 · 점검 · 회수), MCP 를 붙일
  때 백엔드를 다시 고치지 않아도 된다.
